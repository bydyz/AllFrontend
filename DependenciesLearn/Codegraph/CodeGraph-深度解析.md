# 深度解析: CodeGraph

## Step 1: 介绍名词代表的意义

### 1.1 一句话定义
CodeGraph 是一个**本地优先的代码知识图谱工具**，它将任意代码库解析为可查询的知识图谱，供 AI 编码代理消费，从而大幅减少 token 消耗和工具调用次数。

### 1.2 详细定义
- **概念**：CodeGraph 是一种为 AI 编码代理设计的代码智能平台，通过 tree-sitter 解析代码库，构建符号级别的代码属性图（Code Property Graph, CPG），并以 MCP 服务器形式暴露查询接口
- **解决的问题**：AI 编码代理（如 Claude Code、Cursor、Codex）在处理大型代码库时，需要大量 token 来"摸清"代码结构，导致成本高昂、效率低下
- **所属领域**：AI 编码基础设施 / 代码智能 / 开发者工具
- **核心特征**：100% 本地运行、无嵌入向量、无外部 API、MIT 开源协议

## Step 2: 介绍其来由

### 2.1 背景与起源
2025-2026 年，AI 编码代理（Claude Code、Cursor、Codex 等）迅速普及。团队发现月度 token 账单快速增长，根本原因是：**AI 代理在每次任务中花费大量 token 仅用于"理解"代码库结构**——通过 grep、文件读取等工具逐步摸索。传统方案（向量嵌入 + RAG）对代码语义理解效果有限，且需要外部 API，存在数据安全风险。

### 2.2 演进历程
| 时间 | 事件 |
|------|------|
| 2026-01-18 | Colby McHenry 创建 CodeGraph 仓库 |
| 2026-01 ~ 04 | 从 v0.0.1 迭代至 v0.9.5，支持 20+ 语言 |
| 2026-05-26 | 登上 hada.io 热榜第一，GitHub 增长爆发 |
| 2026-05 下旬 | 7 天内获得 21,424 星标，达 #2 GitHub Trending |
| 2026-06-02 | 发布 v0.9.9，接近 v1.0 里程碑 |
| 2026-06-11 | 累计 47.4K 星标、2.9K forks |

### 2.3 创造者的设计考量
- **完全本地化**：不依赖外部 API 或嵌入服务，代码不出本机，满足企业安全要求
- **MCP 原生**：通过 Model Context Protocol 暴露图谱，与主流 AI 代理框架无缝集成
- **符号级精度**：基于真实 AST（抽象语法树）解析，而非猜测，确保调用关系准确
- **增量索引**：支持快速增量更新，避免每次全量重建

## Step 3: 介绍其所能实现的效果

### 3.1 核心功能
| 功能 | 说明 |
|------|------|
| `codegraph_explore` | 从入口点探索代码库，返回相关符号、调用链和源码 |
| `codegraph_search` | 按符号名搜索，返回符号层级结构 |
| `codegraph_node` | 获取单个符号的完整源码 |
| `codegraph_impact` | 分析修改某符号的影响范围（依赖分析） |
| `codegraph_files` | 列出已索引的文件 |
| `codegraph_status` | 查看索引状态 |

### 3.2 使用效果对比
| 指标 | 无 CodeGraph | 有 CodeGraph |
|------|-------------|-------------|
| Token 消耗 | 高（大量 grep/read 调用） | 降低 ~35-47% |
| 工具调用次数 | 频繁 | 减少 ~70% |
| 上下文理解速度 | 慢（逐步摸索） | 快（单次查询获取完整链路） |
| 数据安全性 | 依赖外部服务 | 100% 本地 |

### 3.3 适用场景
- **大型代码库导航**：快速理解陌生代码库的结构和依赖关系
- **重构影响分析**：修改前评估影响范围，降低回归风险
- **新成员上手**：通过图谱查询快速了解项目架构
- **跨语言仓库**：支持 19+ 种语言和 13+ Web 框架
- **企业合规审计**：发现未文档化的依赖或未授权的服务交互

### 3.4 优缺点分析
| 优点 | 缺点 |
|------|------|
| 100% 本地，无数据泄露风险 | 静态分析天花板：反射、元编程等动态特性难以完全捕获 |
| 显著降低 AI 编码成本 | 框架路由解析准确率约 74-84% |
| 符号级精度，非模糊匹配 | 模糊查询（不知道符号名时）无法使用 |
| MIT 开源，社区活跃 | 新语言和内部 DSL 覆盖可能滞后 |
| 增量索引，效率高 | 项目尚未达到 v1.0 稳定版 |

## Step 4: 介绍大体实现过程

### 4.1 整体流程涉及的角色
```
用户 → AI 编码代理 (Claude Code/Cursor/Codex) → CodeGraph MCP Server → SQLite 数据库
                          ↑                                          ↑
                    预索引代码库                              tree-sitter 解析 AST
```

### 4.2 整体流程图
```
┌──────────────┐     ┌──────────────────┐     ┌──────────────┐
│  代码库源码   │ ──→ │  tree-sitter 解析  │ ──→ │  符号关系抽取  │
└──────────────┘     │  (AST 解析)       │     │  调用图/导入链 │
                     └──────────────────┘     └──────┬───────┘
                                                     ↓
┌──────────────┐     ┌──────────────────┐     ┌──────────────┐
│  AI 代理查询  │ ←─ │  MCP Server 暴露  │ ←─ │  SQLite 存储  │
│  (结构化查询) │     │  (图谱查询接口)   │     │  + 全文搜索   │
└──────────────┘     └──────────────────┘     └──────────────┘
```

### 4.3 核心实现原理
1. **代码解析层**：使用 tree-sitter（支持 30+ 语言）将源码解析为 AST
2. **符号抽取层**：从 AST 中提取符号（函数、类、变量等）及其关系（调用、继承、导入）
3. **图谱构建层**：构建代码属性图（CPG），包含符号节点和关系边
4. **存储层**：将图谱存入 SQLite 数据库，建立全文搜索索引
5. **服务层**：通过 MCP 协议暴露查询接口，供 AI 代理调用
6. **增量更新**：监听文件变化，仅重新解析变更部分，避免全量重建

### 4.4 代码示例
```bash
# 安装 CodeGraph
curl -fsSL https://get.codegraph.dev | sh

# 在代码库根目录索引
codegraph index

# 启动 MCP 服务器（供 AI 代理连接）
codegraph serve

# 在 Claude Code 中使用
# AI 代理可通过 MCP 调用 codegraph_explore、codegraph_search 等工具
```

### 4.5 关键 API 说明
| API | 参数 | 返回 |
|-----|------|------|
| `codegraph_explore` | `entry`: 文件路径/函数名/描述 | 符号列表 + 调用链 + 源码 |
| `codegraph_search` | `query`: 搜索关键词 | 匹配的符号及其层级 |
| `codegraph_node` | `symbol_id`: 符号标识 | 符号完整源码 + 位置 |
| `codegraph_impact` | `symbol_id`: 待修改的符号 | 受影响的文件和符号列表 |
| `codegraph_files` | 无 | 已索引文件列表 |
| `codegraph_status` | 无 | 索引统计信息 |
