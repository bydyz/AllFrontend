## 阶段1：探索

### 命令
```bash
/opsx-explore
```

### 目的
自由思考，分析问题空间，不产生代码。

### 做什么
1. 提出澄清性问题、挑战假设
2. 调查代码库，绘制架构图
3. 比较不同方案，评估权衡
4. 识别风险和未知点

### 在 000001 中的实践

**探索目标**：为待办事项应用添加优先级标记功能

**探索过程**：
1. **需求分析**：识别核心需求和用户场景
2. **技术方案探索**：比较不同实现方案
3. **数据结构设计**：设计新的数据结构
4. **UI设计探索**：设计用户界面
5. **风险识别**：识别潜在风险和挑战

**探索产出**：
- 探索记录文档：`openspec/changes/探索记录.md`
- 确定技术方案：图标+颜色方案
- 确定数据结构：添加priority字段

#### 任务4：功能逻辑添加
**修改文件**：`app.js`
```javascript
// 修改addTodo方法
addTodo() {
    const text = this.input.value.trim();
    const priority = this.prioritySelect.value;
    if (!text) return;

    const todo = {
        id: Date.now(),
        text,
        completed: false,
        priority
    };

    this.todos.push(todo);
    this.saveTodos();
    this.render();
    this.input.value = '';
}

// 添加setPriority方法
setPriority(priority) {
    this.currentPriority = priority;
    this.priorityBtns.forEach(btn => {
        btn.classList.toggle('active', btn.dataset.priority === priority);
    });
    this.render();
}

// 修改getFilteredTodos方法
getFilteredTodos() {
    let filtered = this.todos;
    
    if (this.currentFilter === 'pending') {
        filtered = filtered.filter(t => !t.completed);
    } else if (this.currentFilter === 'completed') {
        filtered = filtered.filter(t => t.completed);
    }
    
    if (this.currentPriority !== 'all') {
        filtered = filtered.filter(t => t.priority === this.currentPriority);
    }
    
    return filtered;
}

// 修改render方法
render() {
    const filteredTodos = this.getFilteredTodos();
    
    this.list.innerHTML = filteredTodos.map(todo => `
        <li class="todo-item ${todo.completed ? 'completed' : ''} priority-${todo.priority}">
            <input type="checkbox" ${todo.completed ? 'checked' : ''} 
                   onchange="app.toggleTodo(${todo.id})">
            <span class="priority-dot"></span>
            <span class="todo-text">${todo.text}</span>
            <button class="delete-btn" onclick="app.deleteTodo(${todo.id})">×</button>
        </li>
    `).join('');

    const pendingCount = this.todos.filter(t => !t.completed).length;
    this.pendingCount.textContent = pendingCount;
}
```

## 快捷开发方式

### 方式1：跳过探索阶段
**适用场景**：需求已经很清楚，不需要探索

**步骤**：
```bash
# 直接从提案阶段开始
openspec new change "my-feature"

# 创建文档
# 实施
# 归档
```

### 方式2：使用技能系统
**适用场景**：希望使用自动化工具

**步骤**：
```bash
# 使用探索技能
/opsx-explore

# 使用提案技能
/opsx-propose my-feature

# 使用实施技能
/opsx-apply my-feature

# 使用归档技能
/opsx-archive my-feature
```

### 方式3：命令行快捷方式
**适用场景**：熟悉命令行操作

**步骤**：
```bash
# 快速创建变更
openspec new change "my-feature"

# 查看状态
openspec status --change "my-feature"

# 快速归档
openspec archive "my-feature" -y
```

### 方式4：组合命令
**适用场景**：批量操作

**步骤**：
```bash
# 创建并查看状态
openspec new change "my-feature" && openspec status --change "my-feature"

# 归档并查看结果
openspec archive "my-feature" -y && ls openspec/changes/archive/
```

### 快捷开发对比

| 方式 | 适用场景 | 优点 | 缺点 |
|------|----------|------|------|
| 跳过探索 | 需求明确 | 快速开始 | 可能遗漏细节 |
| 技能系统 | 自动化 | 一站式服务 | 需要技能支持 |
| 命令行 | 熟悉CLI | 灵活高效 | 需要记忆命令 |
| 组合命令 | 批量操作 | 效率高 | 复杂度高 |

## 经验总结

### 成功经验

1. **探索阶段充分**
   - 提前识别风险和挑战
   - 确定最佳技术方案
   - 为后续开发奠定基础

2. **设计文档详细**
   - 技术方案清晰，易于实施
   - 数据结构设计合理
   - UI设计考虑周全

3. **任务分解合理**
   - 任务粒度适中，易于跟踪
   - 依赖关系清晰
   - 进度跟踪方便

4. **测试覆盖全面**
   - 功能测试通过
   - 性能测试达标
   - 兼容性测试完成

### 改进点

1. **UI设计**
   - 可以考虑更优雅的优先级标识方式
   - 可以添加优先级切换的动画效果
   - 可以支持自定义优先级颜色

2. **功能扩展**
   - 可以添加优先级排序功能
   - 可以添加优先级提醒功能
   - 可以添加优先级统计功能

3. **技术优化**
   - 可以优化筛选算法
   - 可以添加拖拽排序功能
   - 可以支持批量操作

### 最佳实践

1. **遵循流程**
   - 按照四个阶段顺序进行
   - 每个阶段都要有产出物
   - 不要跳过必要步骤

2. **文档先行**
   - 先写文档，再写代码
   - 文档要详细，易于理解
   - 文档要与代码同步更新

3. **任务分解**
   - 将大任务分解为小任务
   - 每个任务都要有明确的目标
   - 任务之间要有依赖关系

4. **测试验证**
   - 每个功能都要测试
   - 边界情况要覆盖
   - 性能要达标

## 结论

通过本示例，我们完整演示了使用 OpenSpec 进行开发的四个阶段：探索、提案、实施、归档。每个阶段都有明确的命令、任务和产出物，确保了开发过程的规范性和文档的完整性。

**关键要点**：
1. **探索阶段**：充分思考，确定最佳方案
2. **提案阶段**：详细设计，为实施奠定基础
3. **实施阶段**：按任务列表逐步实现
4. **归档阶段**：清理已完成的变更，保留历史记录

**快捷开发**：可以根据实际情况选择跳过探索阶段、使用技能系统、命令行快捷方式或组合命令，提高开发效率。

**经验总结**：遵循流程、文档先行、任务分解、测试验证是成功的关键。
