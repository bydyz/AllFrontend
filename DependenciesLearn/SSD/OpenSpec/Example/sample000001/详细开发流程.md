# OpenSpec 三步开发流程详解

## 概述

OpenSpec 提供了一种简洁的三步开发流程，适用于大多数项目：

```
propose → apply → archive
```

本示例通过 Sample000001 计算器项目，详细演示这一流程。

## 第一步：Propose（提案）

### 命令

```bash
/opsx-propose <change-name>
```

### 示例

```bash
/opsx-propose sample000001
```

### 作用

创建变更目录并生成所有必要的工件文档：

```
openspec/changes/sample000001/
├── .openspec.yaml          # 变更元数据
├── proposal.md             # 提案文档（做什么 & 为什么）
├── design.md               # 设计文档（怎么做）
├── specs/                  # 规格文档目录
│   └── calculator/
│       └── spec.md         # 功能规格说明
└── tasks.md                # 任务列表
```

### 生成的文档说明

| 文档 | 用途 | 核心内容 |
|------|------|----------|
| `proposal.md` | 定义变更的动机和范围 | Why、What Changes、Capabilities、Impact |
| `design.md` | 技术实现方案 | Context、Goals/Non-Goals、Decisions、Risks |
| `specs/calculator/spec.md` | 功能规格说明 | Requirements、Scenarios |
| `tasks.md` | 实施任务清单 | 分组任务列表，带复选框 |

### 实际执行过程

```bash
# 1. 创建变更
openspec new change "sample000001"

# 2. 获取状态
openspec status --change "sample000001" --json

# 3. 获取各工件的指令并创建文档
openspec instructions proposal --change "sample000001" --json
openspec instructions design --change "sample000001" --json
openspec instructions specs --change "sample000001" --json
openspec instructions tasks --change "sample000001" --json

# 4. 创建文档文件
# - proposal.md
# - design.md
# - specs/calculator/spec.md
# - tasks.md
```

## 第二步：Apply（实施）

### 命令

```bash
/opsx-apply <change-name>
```

### 示例

```bash
/opsx-apply sample000001
```

### 作用

读取任务列表，逐步实现功能，每完成一个任务自动标记为完成。

### 实际执行过程

```bash
# 1. 获取 apply 指令
openspec instructions apply --change "sample000001" --json

# 2. 读取上下文文件
# - proposal.md
# - design.md
# - specs/calculator/spec.md
# - tasks.md

# 3. 按任务列表逐步实现
# 任务列表：
# 1.1 创建 src 目录结构
# 1.2 初始化 package.json 配置
# 2.1 实现加法运算函数 (add)
# 2.2 实现减法运算函数 (subtract)
# 2.3 实现乘法运算函数 (multiply)
# 2.4 实现除法运算函数 (divide)
# 3.1 实现除数为零的错误检查
# 4.1-4.5 编写单元测试
# 5.1 运行测试验证
# 5.2 验证功能符合 specs

# 4. 每完成一个任务，更新 tasks.md
# - [ ] 1.1 创建 src 目录结构  →  - [x] 1.1 创建 src 目录结构
```

### 实施结果

```
✓ 创建 src 目录
✓ 创建 package.json
✓ 实现 calculator.js
✓ 实现所有测试用例
✓ 测试全部通过 (8/8)
```

## 第三步：Archive（归档）

### 命令

```bash
/opsx-archive <change-name>
```

### 示例

```bash
/opsx-archive sample000001
```

### 作用

- 检查所有工件和任务是否完成
- 同步 delta specs 到主 specs
- 移动变更目录到 archive

### 实际执行过程

```bash
# 1. 检查任务完成状态
# 所有任务标记为 [x]

# 2. 同步 specs
# calculator: create
# + 4 added

# 3. 归档变更
mv openspec/changes/sample000001 openspec/changes/archive/2026-07-14-sample000001
```

### 归档结果

```
Task status: ✓ Complete

Specs to update:
  calculator: create
Applying changes to openspec/specs/calculator/spec.md:
  + 4 added

Change 'sample000001' archived as '2026-07-14-sample000001'.
```

## 完整命令汇总

### Propose 阶段

```bash
# 创建变更
openspec new change "sample000001"

# 查看状态
openspec status --change "sample000001" --json

# 获取各工件指令
openspec instructions proposal --change "sample000001" --json
openspec instructions design --change "sample000001" --json
openspec instructions specs --change "sample000001" --json
openspec instructions tasks --change "sample000001" --json
```

### Apply 阶段

```bash
# 获取 apply 指令
openspec instructions apply --change "sample000001" --json

# 查看当前状态
openspec status --change "sample000001"
```

### Archive 阶段

```bash
# 归档变更（跳过确认）
openspec archive sample000001 -y

# 或者带跳过 specs 更新
openspec archive sample000001 -y --skip-specs
```

## 适用场景

### ✅ 适合三步流程的情况

| 场景 | 说明 |
|------|------|
| 简单功能开发 | 需求明确，实现直接 |
| Bug 修复 | 问题清晰，修复方案明确 |
| 小型重构 | 范围可控，风险低 |
| 紧急修复 | 时间紧迫，快速交付 |

### ❌ 需要完整四步流程的情况

| 场景 | 说明 |
|------|------|
| 复杂项目 | 需求不明确，需要探索 |
| 架构设计 | 需要深入分析和讨论 |
| 大型功能 | 涉及多个模块和依赖 |
| 高风险变更 | 需要充分评估和规划 |

## 关键要点

### 1. Propose 是基础

- 定义清楚"做什么"和"为什么"
- 生成完整的文档集合
- 为后续步骤提供上下文

### 2. Apply 是核心

- 按任务列表逐步实现
- 每完成一个任务立即标记
- 遇到问题及时暂停

### 3. Archive 是收尾

- 验证所有任务完成
- 同步 specs 到主目录
- 保持 changes 目录整洁

---

## 常见问题

### Q1: 可以跳过某个步骤吗？

不建议。每个步骤都有其价值：
- Propose：确保方向正确
- Apply：保证实现质量
- Archive：维护项目整洁

### Q2: 遇到问题怎么办？

在 Apply 阶段遇到问题时：
1. 暂停实施
2. 分析问题原因
3. 必要时更新设计文档
4. 继续实施或回退

### Q3: 如何处理需求变更？

1. 回到 Propose 阶段
2. 更新相关文档
3. 重新执行 Apply
4. 最终 Archive

---

## 总结

OpenSpec 的三步开发流程 `propose → apply → archive` 是一种高效、简洁的开发方式。它适用于大多数项目，能够帮助开发者快速交付高质量的代码。

**核心优势**：
- 流程清晰，易于执行
- 文档完整，便于维护
- 任务明确，进度可控
- 归档整洁，历史可追溯

通过本示例的学习，你应该能够熟练使用 OpenSpec 进行项目开发。
