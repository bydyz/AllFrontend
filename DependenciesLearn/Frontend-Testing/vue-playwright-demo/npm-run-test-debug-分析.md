# npm run test:debug 命令分析

## 命令说明

`npm run test:debug` 是一个用于调试测试的命令，对应的脚本是 `npx playwright test --debug`。

### 命令作用
- **npx playwright test**：运行 Playwright Test
- **--debug**：启用调试模式，打开 Playwright Inspector

### 调试模式特点
- **Playwright Inspector**：图形化调试工具
- **交互式调试**：可以单步执行测试
- **实时查看**：观察测试执行过程中的页面状态

## 运行结果

### 调试界面
```
Playwright Inspector 界面包含：
├── 测试文件列表
├── 测试代码视图
├── 页面预览窗口
├── 步骤控制面板
├── 选择器日志
└── 控制台输出
```

### 调试流程
1. 启动调试器
2. 选择测试用例
3. 单步执行测试
4. 检查元素状态
5. 分析测试失败原因

## 结果分析

### 调试模式的优势

1. **交互式调试**
   - 单步执行测试代码
   - 设置断点暂停执行
   - 实时查看变量状态

2. **可视化工具**
   - Playwright Inspector 界面
   - 页面元素高亮显示
   - 选择器日志记录

3. **问题定位**
   - 精确定位测试失败位置
   - 分析元素定位问题
   - 检查页面状态变化

### 调试模式的劣势

1. **执行速度**：调试模式比正常模式慢
2. **手动操作**：需要人工交互
3. **不适合自动化**：无法在 CI/CD 中使用

## 使用场景

### 测试开发阶段
- **编写新测试**：验证测试逻辑是否正确
- **调试失败测试**：分析测试失败原因
- **优化选择器**：找到最佳的元素定位方式

### 问题排查
- **元素定位失败**：检查选择器是否正确
- **测试不稳定**：分析测试时序问题
- **页面状态异常**：检查页面加载和渲染

### 团队协作
- **代码审查**：演示测试执行过程
- **知识传递**：向团队成员解释测试逻辑
- **问题复现**：重现和分析间歇性失败

## 调试技巧

### 1. 单步执行
```javascript
// 在测试代码中添加调试断点
test('调试示例', async ({ page }) => {
  await page.pause()  // 暂停执行
  await page.goto('/')
  // ... 后续代码
})
```

### 2. 选择器日志
- 在 Inspector 中查看选择器匹配情况
- 分析选择器是否正确定位元素
- 优化选择器提高稳定性

### 3. 页面状态检查
- 检查页面加载状态
- 验证元素可见性
- 分析网络请求

### 4. 控制台输出
- 查看 console.log 输出
- 分析 JavaScript 错误
- 检查 API 请求响应

## 常用调试命令

### 运行特定测试
```bash
# 调试特定测试文件
npx playwright test home.spec.js --debug

# 调试匹配的测试用例
npx playwright test -g "计数器应该正确工作" --debug
```

### 使用 page.pause()
```javascript
test('调试测试', async ({ page }) => {
  await page.goto('/')
  await page.pause()  // 暂停执行，打开 Inspector
  // ... 后续代码
})
```

### 调试配置
```javascript
// playwright.config.js
export default defineConfig({
  use: {
    trace: 'on',  // 始终收集追踪信息
  }
})
```

## 注意事项

### 1. 环境要求
- 需要图形界面环境
- 需要安装 Playwright Inspector
- 不支持无图形界面的服务器

### 2. 调试最佳实践
- 先用 debug 模式定位问题
- 修复后用 headed 模式验证
- 最终用 headless 模式自动化

### 3. 常见问题
- **Inspector 不显示**：检查 Playwright 版本
- **调试速度慢**：减少断点数量
- **选择器不稳定**：使用 data-testid 属性
