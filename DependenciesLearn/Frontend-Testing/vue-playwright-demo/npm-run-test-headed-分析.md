# npm run test:headed 命令分析

## 命令说明

`npm run test:headed` 是一个用于在有界面的浏览器中运行测试的命令，对应的脚本是 `npx playwright test --headed`。

### 命令作用
- **npx playwright test**：运行 Playwright Test
- **--headed**：在有界面的浏览器窗口中运行测试（默认是无头模式）

### 与 `npm run test` 的区别
| 特性 | npm run test | npm run test:headed |
|------|--------------|---------------------|
| 浏览器界面 | 无头模式（Headless） | 有界面模式（Headed） |
| 可视化 | 不可见浏览器窗口 | 可见浏览器窗口 |
| 执行速度 | 更快 | 较慢 |
| 调试能力 | 较差 | 便于观察 |
| 适用场景 | CI/CD、自动化 | 调试、开发阶段 |

## 结果分析

### 执行时间对比
| 模式 | 执行时间 | 说明 |
|------|---------|------|
| Headless | 8.2s | 无界面，速度快 |
| Headed | 9.5s | 有界面，速度较慢 |

### Headed 模式的优势

1. **可视化调试**：可以实时看到测试执行过程
2. **问题定位**：快速发现 UI 问题和交互异常
3. **开发体验**：开发阶段更直观地观察测试行为

### Headed 模式的劣势

1. **执行速度**：比无头模式慢10-20%
2. **资源占用**：需要更多系统资源
3. **稳定性**：可能受系统事件影响

## 使用场景

### 开发阶段
- **调试测试用例**：观察测试执行过程
- **验证 UI 交互**：检查元素定位是否正确
- **分析测试失败**：可视化地理解测试失败原因

### 团队协作
- **演示测试**：向团队展示测试流程
- **代码审查**：验证测试覆盖的场景
- **培训新人**：直观地解释测试逻辑

### 不适用场景
- **CI/CD 流水线**：应使用无头模式
- **生产环境测试**：应使用无头模式
- **性能测试**：有界面模式会影响性能

## 常用组合命令

### 单个测试文件
```bash
# 在有界面模式下运行特定测试文件
npx playwright test home.spec.js --headed
```

### 特定测试用例
```bash
# 运行匹配的测试用例
npx playwright test -g "计数器应该正确工作" --headed
```

### 指定浏览器
```bash
# 在特定浏览器中运行
npx playwright test --project=chromium --headed
```

## 注意事项

### 1. 环境要求
- 需要图形界面环境
- Windows/macOS/Linux 桌面环境
- 不支持无图形界面的服务器

### 2. 性能优化
- 开发阶段使用 headed 模式
- CI/CD 使用 headless 模式
- 调试完成后切换回 headless

### 3. 最佳实践
- 调试时使用 headed 模式
- 正式测试使用 headless 模式
- 结合 `--debug` 模式进行深度调试
