## Context

Vite 8 的配置体系包含 7 大分组（shared、server、build、preview、optimizeDeps、ssr、worker），共 80+ 配置项。每个配置项有不同的类型、默认值、关联配置和使用场景。现有学习资料分散在官方文档（英文）和零散的博客中，缺乏系统性的中文整理。

当前状态：`Vite_Configuration/` 下仅有 `build/rollupOptions/input/` 三个层级的文件夹，内容质量不错但覆盖面极小。

## Goals / Non-Goals

**Goals:**
- 构建完整的 Vite 配置层级知识库，覆盖所有官方配置项
- 每个配置项包含：总叙述、配置方式、进阶配置（如有）、注意事项（如有）
- 所有代码示例带中文注释
- 保留已有内容（`build/rollupOptions/input/`），标注废弃配置
- 插件按来源分目录

**Non-Goals:**
- 不翻译官方文档，而是重新组织为中文学习视角
- 不覆盖 Vite 内部实现原理（那是另一个知识库的事）
- 不创建可运行的示例项目（纯文档）
- 不包含 Vite 插件开发指南（那是 Plugin API 的范畴）

## Decisions

### 1. 目录结构：镜像配置层级

**选择**：文件夹结构直接镜像 `vite.config.js` 的配置层级

**理由**：
- 用户看到配置项名称就能定位到对应文件夹
- 和官方文档的结构保持一致，方便对照
- 层级清晰，不会产生歧义

**替代方案**：
- 按功能域分类（dev/build/ssr）→ 问题：`resolve` 等跨域配置难以归类
- 按使用频率排序 → 问题：失去结构化查阅的能力

### 2. 废弃配置处理：保留 + 标注

**选择**：保留 `build/rollupOptions/` 目录，在 README.md 中标注废弃，指向 `build/rolldownOptions/`

**理由**：
- 用户可能在旧项目中遇到 `rollupOptions`，需要了解
- 标注废弃比删除更有教育价值
- 平滑过渡，不破坏已有内容

### 3. 内容模板：四段式

**选择**：每个 README.md 包含以下部分（按需）：
1. **总叙述** — 一句话说明这个配置是什么
2. **配置方式** — 类型、默认值、语法示例
3. **进阶配置** — 高级用法、组合用法、动态配置
4. **注意事项** — 常见坑点、关联配置、版本差异

**理由**：
- 四段式覆盖了"是什么→怎么用→高级用法→注意事项"的完整学习路径
- "按需"原则：简单配置项（如 `clearScreen`）不需要进阶配置部分

### 4. 代码示例风格

**选择**：所有代码示例使用中文注释，关键注释标注在代码行内

**理由**：
- 中文注释降低理解门槛
- 行内注释比行外解释更直观
- 和已有的 `useObject.md` 风格保持一致

### 5. 插件组织：按来源分目录

**选择**：`plugins/@vitejs/plugin-vue/`、`plugins/vite-plugin-svg/` 等

**理由**：
- npm 包名本身就是唯一标识
- 和 npm 生态的命名一致
- 方便扩展新插件

### 6. 数据来源：Vite 8 官方文档

**选择**：以 Vite 8 官方文档（vitejs.dev）为权威来源

**理由**：
- 官方文档是最准确的信息源
- Vite 8 引入了 Rolldown 替代 Rollup，配置项有重大变化
- 中文社区资料质量参差不齐，以官方为准

## Risks / Trade-offs

- **[配置项数量多]** → 分批创建，优先核心配置（shared、build、server），再补充边缘配置（ssr、worker）
- **[Vite 版本更新快]** → 文档中标注适用版本（Vite 8.x），后续可按版本维护
- **[内容深度不一]** → 简单配置项（如 `clearScreen`）只写总叙述+配置方式，不强制四段式
- **[已有内容整合]** → `build/rollupOptions/input/` 内容保留，补充 README.md 说明废弃状态
