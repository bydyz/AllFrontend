# 虚拟滚动核心原理：绝对定位与滚动位置的关系

## 核心困惑

为什么 `position: absolute; top: 0` 的 `list` 能在滚动时跟着内容一起动？容器没有移动，`list` 也没有 `top` 值的变化，它凭什么能"滚动"？

---

## 基础知识：overflow 滚动的到底是什么？

当一个元素设置 `overflow: auto` 或 `overflow: scroll` 时：

- **容器本身（viewport）永远固定在页面上，不做任何物理移动**
- 滚动的是容器内部的 **内容**
- 内容相对于容器发生了 `scrollTop` 像素的偏移

```
初始状态（scrollTop = 0）

┌─────────────────────────┐  ← viewport 容器的"窗户"边界
│██████████████████████████│  ← 内容（整个列表）塞在容器内
│██████████████████████████│     此时内容顶部 = 容器顶部
│██████████████████████████│
│██████████████████████████│
└─────────────────────────┘

滚动后（scrollTop = 1000px）

┌─────────────────────────┐  ← viewport 窗户完全没动
│                         │  ← 上面空出了 1000px（scrollTop）
│██████████████████████████│  ← 内容整体向上推了 1000px
│██████████████████████████│     内容顶部滚到了 viewport 可见区域的 -1000px 处
│██████████████████████████│
│██████████████████████████│
└─────────────────────────┘

容器内的"可见窗口"看到的，就是内容在 -1000px 到 +∞ 范围内的部分
（但容器高度只有 600px，所以实际只看到 -1000px ~ -400px）
```

**关键结论**：滚动是内容的偏移，不是容器的移动。容器永远在那里当"窗户"。

---

## 绝对定位元素在滚动时是什么状态？

绝对定位的规则：**相对于最近的定位祖先，固定在指定坐标上，不随页面其他元素变化而移动**。

在虚拟滚动中：

```vue
<div class="viewport" style="position: relative; overflow: auto;">
  <div class="sizer" style="position: absolute; top: 0;"></div>
  <div class="list" style="position: absolute; top: 0;"></div>
</div>
```

`viewport` 是 `list` 的定位祖先（因为它设置了 `position: relative`）。

当用户滚动时：

| 元素 | 状态 | 原因 |
|------|------|------|
| viewport | **完全不动** | 它是页面上的一块固定区域 |
| list | **完全不动** | 它 `position: absolute; top: 0`，永远钉在 viewport 的左上角 |

**`list` 不会跟着内容一起"滚"**——它钉死在 viewport 左上角，一动不动。

---

## 那为什么内容能"动起来"？transform 的作用

既然 `list` 钉死了，那 `list` 里的内容（可见的 item）怎么能在滚动时看起来也"跟着动"？

答案是：**不用让 list 跟着内容滚，让内容自己滚到位**。

```
滚动前（scrollTop = 0）：
  内容起点 = list 的 top:0 = viewport 的 top:0
  list 内渲染的是 item[0] ~ item[n]

滚动后（scrollTop = 1000px）：
  内容整体向上推了 1000px
  原本的内容起点（item[0]）已经到了 viewport 可见区域的上方 -1000px 处
  现在应该显示 item[16] ~ item[16+n]（第 16 行开始的内容）

  但 list 钉死在 top:0 啊！
  list.top = 0 → list 的左上角 = viewport 的左上角
  → list 里的内容起点还是 0 位置
  → 显示的还是 item[0] ~ item[n]

  错了！怎么办？

  用 transform 把 list 整体向上拉回去：
  list.transform = translateY(-1000px)
  → list 的视觉起点变成 -1000px
  → list 现在"看到"的是内容的 -1000px ~ +∞ 区域
  → 显示的正是 item[16] ~ item[16+n] ✓

  视觉上：list 跟着内容滚了 1000px
  实际上：list 位置没变，是 transform 把它"裁剪"到了正确的位置
```

**核心公式**：

```
list 的真实视觉起点 = list.top（0） + transform.translateY(-scrollTop)
                   = 0 + (-scrollTop)
                   = -scrollTop
                   = 内容的实际滚动距离

所以内容滚到哪里，list 的 transform 就应该把它"拽"到哪里
```

## 图解：三种状态的变化过程

```
初始状态（scrollTop = 0）

viewport（固定不动）
┌─────────────────────────┐
│list (absolute top:0)     │
│ ┌─────────────────────┐ │  list 和内容起点对齐
│ │item[0]  item[1] ...  │ │
│ └─────────────────────┘ │
└─────────────────────────┘

transform: translateY(0)


滚动到 1000px，内容向上推了

viewport（仍然固定不动）
┌─────────────────────────┐
│         ↑ 空白 1000px    │  ← 内容滚上去了，viewport 上方空出来了
│list (absolute top:0)     │  ← list 本身没动，还钉在 top:0
│ ┌─────────────────────┐ │
│ │item[16] item[17]...  │ │  ← 但通过 transform，list 看到的是 1000px 以后的内容
│ └─────────────────────┘ │     显示的是 item[16] 起的内容 ✓
└─────────────────────────┘

transform: translateY(-1000px)


再滚动到 2000px

viewport
┌─────────────────────────┐
│         ↑ 空白 2000px    │
│list (absolute top:0)     │
│ ┌─────────────────────┐ │
│ │item[33] item[34]...  │ │  ← 显示的是 item[33] 起的内容
│ └─────────────────────┘ │
└─────────────────────────┘

transform: translateY(-2000px)
```

**总结**：绝对定位元素在滚动事件中**真的完全不动**，是 `transform` 的位移偏移了它的视觉裁剪区域，让人觉得它"跟着滚了"。

---

## 为什么选 transform 而不是改 top 值？

| 方案 | 效果 | 性能 |
|------|------|------|
| `list.style.top = scrollTop + 'px'` | list 物理移动到新位置 | 触发 Layout（重排），昂贵 |
| `list.style.transform = translateY(-scrollTop + 'px')` | list 视觉偏移，物理位置不变 | GPU 合成，不触发 Layout |

`transform` 由浏览器的**合成线程**处理，不经过主线程的 Layout/Paint 流程，所以可以跑到 60fps。改 `top` 值则需要主线程重新计算布局，滚动时会卡顿。

---

## 一句话总结

> 滚动是内容的位移，不是容器的位移。绝对定位的元素**真的不动**，是 `transform: translateY()` 把它的视觉裁剪窗口偏移到了内容滚到的位置，产生了"跟着滚"的视觉效果，同时享有 GPU 合成的性能优势。
