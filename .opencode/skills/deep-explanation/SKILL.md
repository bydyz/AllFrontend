---
name: deep-explanation
description: 深度解释技术概念和名词。当用户想深入理解某个技术术语、概念、框架、工具的含义、来由、实现原理时使用。适用于"什么是X"、"X是怎么来的"、"X是如何工作的"等场景。
---

对输入的概念进行四步深度解析。

**Input**: 指定要解释的概念名称。可以通过两种方式：
- 方式1：加载 skill 后手动输入概念名称
- 方式2：使用命令时直接传入，如 `/deep-explain Function Call` 或 `用 deep-explanation 解析 Function Call`

**Steps**

1. **提取概念名称**

   - 首先检查 $ARGUMENTS 是否已提供概念名称：
     - 如果 $ARGUMENTS 不为空，使用正则提取概念名称
     - 匹配模式：去除常见前缀（如"解析"、"介绍"、"什么是"、"讲解"、"分析"、"深度解析"等）
     - 提取剩余的核心概念作为解析目标
     - 如果提取结果为空，使用原始 $ARGUMENTS
   - 如果 $ARGUMENTS 为空，则询问用户"请告诉我你想深入理解的概念名称是什么？"
   - 等待用户输入概念名称后，继续下一步

   查找文件：`{skill目录}/exports/{概念名}-深度解析.md`
   
   - 如果存在：询问用户"已存在该概念的解析文档，是否需要查看？或者重新生成？"
   - 如果用户要求查看，直接读取返回
   - 如果不存在，继续下一步

2. **Step 1: 介绍名词代表的意义**

   - 一句话定义
   - 详细定义（概念是什么、解决什么问题、属于哪个技术领域）
   - 概念卡片

3. **Step 2: 介绍其来由**

   - 背景与起源
   - 演进历程（时间线）
   - 创造者的设计考量

4. **Step 3: 介绍其所能实现的效果**

   - 核心功能
   - 使用效果对比
   - 适用场景
   - 优缺点分析

5. **Step 4: 介绍大体实现过程**

   - 整体流程涉及的角色（如有）
   - 整体流程图
   - 核心实现原理
   - 代码示例
   - 关键API说明

6. **自动保存**

   生成完成后，自动保存到：
   `{skill目录}/exports/{概念名}-深度解析.md`

7. **交互确认**

   生成内容后，询问用户：
   ```
   这部分内容已经完成，请确认是否满足要求？如果有需要调整的地方，请告诉我。
   ```

   - 如果用户不满意，根据反馈修改后再次确认
   - 只有当用户明确表示「ok」「可以」「满意」时，才认为本次解析完成

**Output 示例**

```

#### 1.2 详细定义
- 概念：Promise 是异步编程的解决方案
- 场景：处理网络请求、文件读取等异步操作
- 解决问题：回调地狱、异步代码可读性差
- 所属领域：JavaScript 异步编程

#### 1.3 概念卡片

├─────────────────────────────────────────┤

│  所属领域: JavaScript                  │
│  解决问题: 回调地狱                    │
└─────────────────────────────────────────┘

### Step 2: 介绍其来由
...
```

**Guardrails**

- 生成后必须询问用户是否满足要求
- 只有用户明确表示「ok」才能结束
- 自动保存文档到本地文件
- 如果概念涉及多角色，先在文档中固化角色信息
- 保持解析内容的技术准确性和完整性
