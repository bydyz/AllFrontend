---
name: deep-explanation
description: 深度解释技术概念和名词。当用户想深入理解某个技术术语、概念、框架、工具的含义、来由、实现原理时使用。适用于"什么是X"、"X是怎么来的"、"X是如何工作的"等场景。
---

对输入的概念进行四步深度解析。

**Input**: 指定要解释的概念名称。可以通过两种方式：
- 方式1：加载 skill 后手动输入概念名称
- 方式2：使用命令时直接传入，如 `/deep-explain Function Call` 或 `用 deep-explanation 解析 Function Call`

**Steps**

1. **提取概念名称**

   - 首先检查 $ARGUMENTS 是否已提供概念名称：
     - 如果 $ARGUMENTS 不为空，使用正则提取概念名称
     - 匹配模式：去除常见前缀（如"解析"、"介绍"、"什么是"、"讲解"、"分析"、"深度解析"等）
     - 提取剩余的核心概念作为解析目标
     - 如果提取结果为空，使用原始 $ARGUMENTS
   - 如果 $ARGUMENTS 为空，则询问用户"请告诉我你想深入理解的概念名称是什么？"
   - 等待用户输入概念名称后，继续下一步

2. **Step 1: 介绍名词代表的意义**

   - 一句话定义
   - 详细定义（概念是什么、解决什么问题、属于哪个技术领域）
   - 概念卡片

3. **Step 2: 介绍其来由**

   - 背景与起源
   - 演进历程（时间线）
   - 创造者的设计考量

4. **Step 3: 介绍其所能实现的效果**

   - 核心功能
   - 使用效果对比
   - 适用场景
   - 优缺点分析

5. **Step 4: 介绍大体实现过程**

   - 整体流程涉及的角色（如有）
   - 整体流程图
   - 核心实现原理
   - 代码示例
   - 关键API说明

6. **交互确认（循环流程）**

    6.1 **初次展示与确认**

    生成内容后，展示给用户并询问：
    ```
    这部分内容已经完成，请确认是否满足要求？如果有需要调整的地方，请告诉我。
    ```

    6.2 **用户反馈**

    - 用户明确表示「ok」「可以」「满意」→ 进入步骤 7（询问存储位置）
    - 用户提出修改意见 → 进入 6.3

    6.3 **修改内容**

    - 根据用户反馈修改文档内容
    - 修改完成后，向用户展示**改动前后对比**（指出修改了哪些部分、原来的内容是什么、改成了什么）

    6.4 **再次确认**

    展示改动后，再次询问用户：
    ```
    已根据您的反馈修改完成，请确认是否满足要求？如果有需要继续调整的地方，请告诉我。
    ```

    - 用户满意 → 进入步骤 7
    - 用户不满意 → 返回 6.3 继续循环，直到用户明确表示满意

7. **询问存储位置**

   当用户确认内容满足要求后，询问用户：
   ```
   请问您希望将文档存储在哪个文件夹？请提供完整的文件夹路径。
   ```

   - 等待用户输入文件夹路径
   - 如果用户输入的路径不存在，询问是否创建该文件夹
   - 如果用户输入的路径有效，继续下一步

8. **保存文档**

   在用户指定的文件夹中创建文档：
   `{用户指定的文件夹}/{概念名}-深度解析.md`

**Output 示例**

```
## 深度解析: Promise

### Step 1: 介绍名词代表的意义

#### 1.1 一句话定义
Promise 是 JavaScript 中用于处理异步操作的对象，代表一个异步操作的最终结果。

#### 1.2 详细定义
- 概念：Promise 是异步编程的解决方案
- 场景：处理网络请求、文件读取等异步操作
- 解决问题：回调地狱、异步代码可读性差
- 所属领域：JavaScript 异步编程

#### 1.3 概念卡片
┌─────────────────────────────────────────┐
│  概念: Promise                          │
├─────────────────────────────────────────┤
│  一句话定义: 异步操作的对象            │
│  所属领域: JavaScript                  │
│  解决问题: 回调地狱                    │
└─────────────────────────────────────────┘

### Step 2: 介绍其来由
...
```

**Guardrails**

- 生成后必须询问用户是否满足要求
- 用户明确表示「ok」后，询问用户要将文档存储在哪里
- 用户输入具体的文件夹后，再在文件夹中创建文档
- 如果概念涉及多角色，先在文档中固化角色信息
- 保持解析内容的技术准确性和完整性
