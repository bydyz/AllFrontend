## 详细层次解析

### 第1层：EventTarget —— 所有可事件对象的绝对基类

`EventTarget` 是 Web API 事件系统的根基，任何可以接收、处理或触发事件的对象都继承自它。

```javascript
// EventTarget 可以直接实例化
const customTarget = new EventTarget();
customTarget.addEventListener('custom', () => console.log('事件触发'));

// 验证常见对象是否继承自 EventTarget
console.log(window instanceof EventTarget);           // true
console.log(document instanceof EventTarget);         // true
console.log(document.body instanceof EventTarget);    // true
console.log(new XMLHttpRequest() instanceof EventTarget); // true
console.log(new WebSocket('ws://localhost') instanceof EventTarget); // true
console.log(new AudioContext() instanceof EventTarget); // true
```

#### EventTarget 核心方法

| 方法 | 说明 | 返回值 |
|:---|:---|:---|
| `addEventListener(type, listener, options)` | 注册事件监听器 | `void` |
| `removeEventListener(type, listener, options)` | 移除事件监听器 | `void` |
| `dispatchEvent(event)` | 触发事件 | `boolean` |

```javascript
// addEventListener 第三个参数详解
element.addEventListener('click', handler, {
  capture: false,    // 是否在捕获阶段触发
  once: false,       // 是否只触发一次
  passive: false,    // 是否不会调用 preventDefault()
  signal: controller.signal  // 通过 AbortController 绑定生命周期
});

// 使用 AbortController 批量移除监听器
const controller = new AbortController();
element.addEventListener('click', handler1, { signal: controller.signal });
element.addEventListener('click', handler2, { signal: controller.signal });
controller.abort(); // 一次性移除所有通过此 signal 注册的监听器
```

## 事件传播机制

事件在 DOM 中的传播分为三个阶段：

```
                    捕获阶段                目标阶段    冒泡阶段
window → document → body → div ────────→ div ────────→ div → body → document → window
        (从外到内)                    (触发事件)    (从内到外)
```

### 事件传播阶段

| 阶段 | 说明 | 顺序 |
|:---|:---|:---|
| **捕获阶段 (Capture)** | 事件从 `window` 向下传播到目标元素 | 外 → 内 |
| **目标阶段 (Target)** | 事件到达实际触发的元素 | - |
| **冒泡阶段 (Bubble)** | 事件从目标元素向上传播到 `window` | 内 → 外 |

```javascript
// 事件传播演示
<div id="outer">
  <div id="inner">
    <button id="btn">点击</button>
  </div>
</div>

<script>
const outer = document.getElementById('outer');
const inner = document.getElementById('inner');
const btn = document.getElementById('btn');

// 默认在冒泡阶段触发
outer.addEventListener('click', () => console.log('outer 冒泡'));
inner.addEventListener('click', () => console.log('inner 冒泡'));
btn.addEventListener('click', () => console.log('btn 冒泡'));

// 捕获阶段触发（第三个参数为 true 或 { capture: true }）
outer.addEventListener('click', () => console.log('outer 捕获'), true);
inner.addEventListener('click', () => console.log('inner 捕获'), true);

// 输出顺序：
// outer 捕获 → inner 捕获 → btn 冒泡 → inner 冒泡 → outer 冒泡
</script>
```

### 事件对象核心属性

| 属性 | 说明 |
|:---|:---|
| `event.target` | 触发事件的元素 |
| `event.currentTarget` | 绑定事件监听器的元素 |
| `event.type` | 事件类型（如 'click'） |
| `event.bubbles` | 是否冒泡 |
| `event.cancelable` | 是否可取消 |
| `event.defaultPrevented` | 是否已调用 `preventDefault()` |
| `event.timeStamp` | 事件创建时间 |
| `event.isTrusted` | 是否由浏览器触发（区分真实/合成事件） |

### 阻止事件传播

```javascript
element.addEventListener('click', (e) => {
  // 阻止事件继续冒泡（或捕获）
  e.stopPropagation();
  
  // 阻止同一元素上其他监听器执行
  e.stopImmediatePropagation();
  
  // 阻止浏览器默认行为（如链接跳转、表单提交）
  e.preventDefault();
});
```

## 自定义事件

使用 `CustomEvent` 可以创建带有自定义数据的事件。

### 基本用法

```javascript
// 创建自定义事件
const event = new CustomEvent('userLogin', {
  detail: { username: 'admin', role: 'admin' }, // 自定义数据
  bubbles: true,      // 允许冒泡
  cancelable: true    // 允许取消
});

// 监听自定义事件
element.addEventListener('userLogin', (e) => {
  console.log('用户登录:', e.detail.username);
  console.log('用户角色:', e.detail.role);
});

// 触发自定义事件
element.dispatchEvent(event);
```

### 自定义事件封装

```javascript
// 封装事件触发器
function emitEvent(element, eventName, data) {
  const event = new CustomEvent(eventName, {
    detail: data,
    bubbles: true,
    cancelable: true
  });
  return element.dispatchEvent(event);
}

// 使用
emitEvent(document, 'app:ready', { version: '1.0' });
emitEvent(window, 'theme:change', { theme: 'dark' });
```

## 性能优化与最佳实践

### 事件委托

利用事件冒泡机制，将子元素的事件处理委托给父元素：

```javascript
// ❌ 为每个 li 绑定事件（性能差）
document.querySelectorAll('li').forEach(li => {
  li.addEventListener('click', handleClick);
});

// ✅ 事件委托（性能好）
document.querySelector('ul').addEventListener('click', (e) => {
  if (e.target.tagName === 'LI') {
    handleClick(e);
  }
});

// ✅ 更优雅的委托方式
document.querySelector('ul').addEventListener('click', (e) => {
  const li = e.target.closest('li');
  if (li && this.contains(li)) {
    handleClick(e, li);
  }
});
```

### 内存管理：及时移除监听器

```javascript
// 组件卸载时移除监听器
class MyComponent {
  constructor() {
    this.handleResize = this.handleResize.bind(this);
    window.addEventListener('resize', this.handleResize);
  }
  
  destroy() {
    window.removeEventListener('resize', this.handleResize);
  }
  
  handleResize() {
    console.log('窗口大小改变');
  }
}

// 使用 AbortController 管理多个监听器
class DataLoader {
  constructor() {
    this.controller = new AbortController();
  }
  
  init() {
    const { signal } = this.controller;
    
    window.addEventListener('online', this.handleOnline, { signal });
    window.addEventListener('offline', this.handleOffline, { signal });
    document.addEventListener('visibilitychange', this.handleVisibility, { signal });
  }
  
  destroy() {
    this.controller.abort(); // 一次性移除所有监听器
  }
}
```

### once 选项：一次性监听器

```javascript
// 只触发一次的事件

// 等价于
```

### 避免在事件处理中执行耗时操作

```javascript
// ❌ 阻塞主线程

  // 每次输入都执行复杂计算
  const result = expensiveCalculation(e.target.value);
  updateUI(result);
});

// ✅ 使用防抖
input.addEventListener('input', debounce((e) => {
  const result = expensiveCalculation(e.target.value);
  updateUI(result);
}, 300));

// ✅ 使用节流
window.addEventListener('scroll', throttle(() => {
  updateScrollIndicator();
}, 100));
```

## 总结

### 继承链设计原则

EventTarget 继承链体现了优秀的**关注点分离**设计：

| 层级 | 职责 | 核心能力 |
|:---|:---|:---|
| `EventTarget` | 事件系统 | `addEventListener`, `removeEventListener`, `dispatchEvent` |
| `Node` | DOM 树操作 | 节点关系、增删改查、克隆 |
| `Element` | 元素通用功能 | 选择器、属性操作、类名操作 |
| `HTMLElement` | HTML 特性 | 内容、样式、交互、元数据 |
| 具体元素 | 特定功能 | 输入值、链接地址、媒体控制等 |

### 关键要点

1. **所有 DOM 节点都是 EventTarget**：包括元素、文本、注释、文档等
2. **事件传播分三阶段**：捕获 → 目标 → 冒泡
3. **事件委托提升性能**：利用冒泡机制减少监听器数量
4. **及时清理监听器**：避免内存泄漏
5. **使用现代 API**：`AbortController`、`once`、`passive` 等
