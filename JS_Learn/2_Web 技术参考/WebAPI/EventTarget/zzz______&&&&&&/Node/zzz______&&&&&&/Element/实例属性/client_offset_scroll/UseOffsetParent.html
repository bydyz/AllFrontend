历史意义：在 IE 6/7 和早期浏览器时代，getBoundingClientRect() 这个 API 不仅性能差，而且在某些浏览器中精度有问题（会忽略边框）。那时候，想要获取一个元素在页面中的绝对坐标，唯一的兼容办法就是写一个 while 循环，不断往上累加 offsetTop/Left。这是那个年代的“标准 polyfill”。
现代意义：
1.有更简单的替代品：element.getBoundingClientRect() 加上滚动偏移，一行代码就能拿到精确坐标，而且性能极佳。
2.容易被 CSS 属性“坑”：只要父级加了 transform、filter 或 will-change，offsetParent 链就会被打断（甚至变成 null），导致累加出来的数字完全错误。现在项目中动画和 3D 变换太常见了，这个方法极不可靠。
现代还能用上的场景，那就是在滚动容器内计算相对偏移。
