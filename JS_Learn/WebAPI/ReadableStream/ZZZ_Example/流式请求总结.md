# 流式请求与 ReadableStream 总结

## 问题 1：流式请求是否使用 ReadableStream 实现？

是的。在现代浏览器中，`fetch` 请求的响应体就是 `ReadableStream` 类型。

```js
const response = await fetch('/api/data');
const body = response.body; // 这是一个 ReadableStream
```

通过 `getReader()` 可以读取流数据：

```js
const reader = response.body.getReader();
const decoder = new TextDecoder();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  console.log(decoder.decode(value));
}
```

这实现了真正的流式处理，是 SSE、分块传输、大文件流式下载的基础。

## 问题 2：response 是 ReadableStream 实例吗？为什么要加 .body？

`response` 不是 `ReadableStream` 实例，而是 `Response` 对象（Fetch API 的实例），包含状态码、头部等元数据。

`.body` 是 `Response` 上的属性，返回实际的响应体 `ReadableStream`。

```
Response 对象
├── ok, status, statusText  (元数据)
├── headers
├── url
└── body ← 这里才是 ReadableStream
```

将元数据和数据分离的设计允许先检查 `response.ok` 或 `response.headers`，再决定是否读取流。
