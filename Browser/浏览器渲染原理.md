# 浏览器渲染原理

## 一、渲染的本质

渲染就是将一个 HTML 字符串，经过一系列复杂运算，最终变成屏幕上每个像素点的颜色信息。

你可以把它想象成一个函数：输入是页面源码（HTML/CSS/JS 文本），输出是整个页面的像素颜色矩阵，交给 GPU/显卡即可显示。

```javascript
// 渲染过程的伪代码表示
function render(htmlContent) {
  // 1. 解析阶段
  const domTree = parseHTML(htmlContent);      // 解析 HTML 生成 DOM 树
  const cssomTree = parseCSS(cssContent);      // 解析 CSS 生成 CSSOM 树
  
  // 2. 样式计算阶段
  const computedStyleDom = calculateStyles(domTree, cssomTree);
  
  // 3. 布局阶段
  const layoutTree = layout(computedStyleDom);  // 计算几何信息
  
  // 4. 分层阶段
  const layerTree = layer(layoutTree);          // 分层优化重绘
  
  // 5. 绘制阶段
  const paintInstructions = paint(layerTree);   // 生成绘制指令
  
  // 6. 分块阶段
  const tiles = tiling(paintInstructions);      // 划分为小块
  
  // 7. 光栅化阶段
  const bitmaps = rasterize(tiles);             // 转换为位图
  
  // 8. 合成显示阶段
  composite(bitmaps);                           // 合成并显示到屏幕
}
```

## 二、渲染的启动时机

1. 网络线程下载到 HTML 文档后，生成一个渲染任务，放入消息队列
2. 渲染主线程通过事件循环取出该任务，正式启动渲染流程

```javascript
// 事件循环机制简化示意
while (true) {
  // 1. 从消息队列取出任务
  const task = messageQueue.dequeue();
  
  // 2. 执行任务（可能是渲染任务、JS 执行任务等）
  if (task.type === 'render') {
    // 渲染主线程执行渲染流程
    executeRenderPipeline(task.htmlContent);
  } else if (task.type === 'script') {
    // 执行 JavaScript
    executeScript(task.script);
  }
  
  // 3. 处理微任务
  processMicroTasks();
}
```

**面试第一句话即可点明：** "当浏览器的网络线程收到一篇文档后，会产生一个渲染任务，并将其传递给渲染主线程的消息队列。"

## 四、各步骤详解

### 1. 解析 HTML（Parse HTML）

**输入：** HTML 字符串  
**输出：** DOM 树 + CSSOM 树

```html
<!-- 示例 HTML -->
<div class="container">
  <h1>标题</h1>
  <p>段落文字</p>
</div>
```

```javascript
// DOM 树结构示意
const domTree = {
  type: 'element',
  tagName: 'html',
  children: [
    {
      type: 'element',
      tagName: 'head',
      children: []
    },
    {
      type: 'element',
      tagName: 'body',
      children: [
        {
          type: 'element',
          tagName: 'div',
          attributes: { class: 'container' },
          children: [
            {
              type: 'element',
              tagName: 'h1',
              children: [{ type: 'text', content: '标题' }]
            },
            {
              type: 'element',
              tagName: 'p',
              children: [{ type: 'text', content: '段落文字' }]
            }
          ]
        }
      ]
    }
  ]
};
```

**关键优化：**
- 浏览器会启动**预解析线程**，提前下载和解析外部 CSS/JS
- CSS 不会阻塞 HTML 解析，因为解析 CSS 的工作在预解析线程中完成，与主线程并行
- JS 会阻塞 HTML 解析，因为 JS 可能会修改 DOM 树，所以主线程遇到 `<script>` 时必须暂停解析，等待 JS 下载并执行完毕

```html
<!-- 阻塞示例 -->
<head>
  <!-- CSS 不阻塞 HTML 解析，但会阻塞渲染（渲染树构建需要 CSSOM） -->
  <link rel="stylesheet" href="style.css">
  
  <!-- JS 会阻塞 HTML 解析 -->
  <script src="app.js"></script>
</head>

<!-- 优化方案 -->
<head>
  <!-- async: 异步下载，下载完立即执行，执行时阻塞 HTML 解析 -->
  <script async src="app.js"></script>
  
  <!-- defer: 异步下载，HTML 解析完后按顺序执行 -->
  <script defer src="app.js"></script>
</head>
```

**面试回答：** "CSS 不阻塞 HTML 解析，但 JS 会阻塞。"

### 2. 样式计算（Style Calculation）

**输入：** DOM 树 + CSSOM 树  
**输出：** 带有**最终样式（Computed Style）**的 DOM 树

```css
/* CSS 示例 */
.container {
  color: red;
  font-size: 16px;
  margin: 10px;
}

h1 {
  font-size: 2em;  /* 相对单位 */
}
```

```javascript
// 样式计算过程示意
const computedStyles = {
  '.container': {
    color: 'rgb(255, 0, 0)',      // red → rgb(255, 0, 0)
    fontSize: '16px',             // 16px → 16px
    margin: {
      top: '10px',
      right: '10px',
      bottom: '10px',
      left: '10px'
    }
  },
  'h1': {
    fontSize: '32px',             // 2em → 32px (基于父元素 16px)
    color: 'rgb(255, 0, 0)',      // 继承自 .container
    margin: {
      top: '0px',
      right: '0px',
      bottom: '0px',
      left: '0px'
    }
  }
};

// 在 JS 中获取计算后的样式
const element = document.querySelector('.container');
const computedStyle = window.getComputedStyle(element);

console.log(computedStyle.color);      // "rgb(255, 0, 0)"
console.log(computedStyle.fontSize);   // "16px"
console.log(computedStyle.marginTop);  // "10px"
```

**关键点：**
- 预设值（如 `red`）会转为绝对值（如 `rgb(255,0,0)`）
- 相对单位（如 `em`）会转为绝对单位（如 `px`）
- 这一步会用到 CSS 属性值计算过程（包含层叠、继承、优先级等）

### 3. 布局（Layout）

**输入：** 带有样式的 DOM 树  
**输出：** 布局树（包含每个节点的尺寸和位置）

```css
/* 布局相关 CSS */
.container {
  width: 200px;
  height: 100px;
  padding: 10px;
  margin: 20px;
}

.box {
  width: 50%;
  height: 50%;
}
```

```javascript
// 布局树结构示意
const layoutTree = {
  type: 'LayoutBlock',
  tagName: 'div',
  attributes: { class: 'container' },
  geometry: {
    x: 20,      // 相对于包含块的 x 坐标
    y: 20,      // 相对于包含块的 y 坐标
    width: 200, // 内容宽度
    height: 100 // 内容高度
  },
  children: [
    {
      type: 'LayoutBlock',
      tagName: 'div',
      attributes: { class: 'box' },
      geometry: {
        x: 10,   // padding + 父元素坐标
        y: 10,
        width: 100,  // 200 * 50%
        height: 50   // 100 * 50%
      }
    }
  ]
};

// 获取元素的布局信息
const container = document.querySelector('.container');
console.log(container.offsetWidth);   // 220px (width + padding-left + padding-right)
console.log(container.offsetHeight);  // 120px (height + padding-top + padding-bottom)
console.log(container.clientWidth);   // 200px (width + padding)
console.log(container.clientHeight);  // 100px (height + padding)
console.log(container.offsetTop);     // 20px
console.log(container.offsetLeft);    // 20px
```

**布局树与 DOM 树的区别：**
- `display: none` 的元素没有几何信息，不会出现在布局树中
- 伪元素（`::before`/`::after`）在 DOM 树中不存在，但在布局树中存在
- 匿名行盒/匿名块盒等也会在布局树中生成

```html
<!-- 示例 -->
<div style="display: none;">我不会出现在布局树中</div>
<div>我会出现在布局树中</div>

<style>
  /* 伪元素在布局树中存在 */
  .text::before {
    content: "前缀：";
  }
</style>
```

### 4. 分层（Layer）

**输入：** 布局树  
**输出：** 分层树（将页面分成多个图层）

```javascript
// 分层策略示意
const layerTree = {
  root: {
    layerId: 1,
    stackingContext: true,
    children: [
      {
        layerId: 2,
        stackingContext: true,
        reason: 'z-index: 1',
        element: '<div style="z-index: 1;">...</div>'
      },
      {
        layerId: 3,
        stackingContext: true,
        reason: 'will-change: transform',
        element: '<div style="will-change: transform;">...</div>'
      }
    ]
  }
};
```

**影响分层的因素：**
- `z-index`、`opacity`、`transform` 等与堆叠上下文相关的属性
- `will-change` 可提示浏览器将某元素单独分层（但不可滥用，内存占用增加）

```css
/* 触发分层的属性示例 */
.element-1 {
  z-index: 10;              /* 创建新的堆叠上下文 */
}

.element-2 {
  opacity: 0.5;             /* 创建新的堆叠上下文 */
}

.element-3 {
  transform: rotate(45deg); /* 创建新的堆叠上下文 */
}

/* will-change 建议浏览器分层，但要谨慎使用 */
.element-4 {
  will-change: transform;   /* 提示浏览器可能需要分层 */
}

/* 不要滥用 will-change */
.bad-practice {
  will-change: transform, opacity, width, height;  /* ✗ 内存占用过大 */
}
```

### 5. 绘制（Paint）

**输入：** 分层树  
**输出：** 每一层的**绘制指令集**

```javascript
// 绘制指令示意（类似 Canvas API）
const paintInstructions = [
  // 绘制 .container 元素
  { type: 'FillRect', x: 20, y: 20, width: 200, height: 100, color: 'white' },
  { type: 'StrokeRect', x: 20, y: 20, width: 200, height: 100, color: 'black' },
  
  // 绘制 h1 文字
  { type: 'SetFont', size: '32px', family: 'Arial' },
  { type: 'FillText', text: '标题', x: 30, y: 50, color: 'rgb(255, 0, 0)' },
  
  // 绘制 p 文字
  { type: 'SetFont', size: '16px', family: 'Arial' },
  { type: 'FillText', text: '段落文字', x: 30, y: 80, color: 'rgb(255, 0, 0)' }
];

// 注意：这一步还不是真正的像素绘制，只是生成指令
// 主线程完成此步骤后，将指令交给合成线程，主线程不再参与后续工作
```

### 6. 分块（Tiling）

**输入：** 每一层的绘制指令  
**输出：** 将每一层划分为多个**小块（Tile）**

```
┌─────────────────────────────────────────────────────────┐
│                        分层                              │
│  ┌─────────┬─────────┬─────────┬─────────┐              │
│  │  Tile1  │  Tile2  │  Tile3  │  Tile4  │  ← 优先处理  │
│  ├─────────┼─────────┼─────────┼─────────┤    靠近视口  │
│  │  Tile5  │  Tile6  │  Tile7  │  Tile8  │    的小块    │
│  ├─────────┼─────────┼─────────┼─────────┤              │
│  │  Tile9  │ Tile10  │ Tile11  │ Tile12  │              │
│  └─────────┴─────────┴─────────┴─────────┘              │
│                    视口 (Viewport)                        │
└─────────────────────────────────────────────────────────┘
```

**关键点：**
- 由**合成线程**负责
- 合成线程会从**线程池**中获取多个线程并行分块，提高效率
- 分块的目的是优先处理靠近视口（屏幕）的小块，尽早显示内容

### 7. 光栅化（Rasterization）

**输入：** 分块信息  
**输出：** 每个小块的**位图（每个像素点的颜色信息）**

```javascript
// 光栅化过程示意
// 将矢量图形转换为像素数据

// 原始矢量数据
const vectorData = {
  type: 'Rectangle',
  x: 20, y: 20,
  width: 200, height: 100,
  color: '#ffffff'
};

// 光栅化后的位图数据（示意）
const bitmapData = {
  width: 200,
  height: 100,
  pixels: [
    // [R, G, B, A] 每个像素的 RGBA 值
    [255, 255, 255, 255],  // 第一个像素
    [255, 255, 255, 255],  // 第二个像素
    // ... 数万个像素
  ]
};
```

**关键点：**
- 此过程由 **GPU 进程**加速，GPU 擅长并行处理图像数据
- 优先光栅化靠近视口的小块，以快速呈现首屏

### 8. 画（Composite / Draw）

**输入：** 所有小块的位图  
**输出：** 屏幕上的最终像素

```javascript
// 合成过程示意
const drawQuads = [
  {
    bitmapId: 'tile-1',
    position: { x: 0, y: 0 },
    transform: null  // 无变换
  },
  {
    bitmapId: 'tile-2',
    position: { x: 200, y: 0 },
    transform: {
      type: 'rotate',
      angle: 45,  // 度
      origin: { x: 100, y: 50 }
    }
  }
];

// 由于渲染进程处于沙盒中，无法直接操作硬件
// 需通过 GPU 进程中转，最终调用系统接口，由显卡完成屏幕显示

// transform 操作在此步骤完成，不涉及主线程，因此效率极高
```

**关键点：**
- 合成线程生成**指引信息（Draw Quads）**
- 渲染进程处于**沙盒**中，无法直接操作硬件
- `transform` 操作在此步骤完成，不涉及主线程，因此效率极高

## 五、重排（Reflow）与重绘（Repaint）

### 重排（Reflow）

**触发条件：** 修改了影响几何信息的操作

```javascript
// ❌ 会触发重排的操作
element.style.width = '200px';        // 改变宽高
element.style.margin = '20px';        // 改变边距
element.style.fontSize = '20px';      // 改变字体大小
document.body.appendChild(newElement); // 增删 DOM 元素

// ⚠️ 读取几何属性会强制同步触发重排
const width = element.offsetWidth;     // 读取 offsetWidth
const height = element.offsetHeight;   // 读取 offsetHeight

// ❌ 不推荐：多次操作导致多次重排
element.style.width = '200px';
element.style.height = '100px';
element.style.margin = '10px';

// ✅ 推荐：合并操作，使用文档碎片
const fragment = document.createDocumentFragment();
const newElement1 = document.createElement('div');
const newElement2 = document.createElement('div');
// ... 设置样式和内容
fragment.appendChild(newElement1);
fragment.appendChild(newElement2);
document.body.appendChild(fragment);  // 只触发一次重排
```

**优化方案：**
```javascript
// ❌ 错误：读写分离导致多次重排
for (let i = 0; i < 100; i++) {
  element.style.width = `${i}px`;
  console.log(element.offsetWidth);  // 每次循环都强制同步重排
}

// ✅ 正确：批量读取，批量写入
const width = element.offsetWidth;    // 先读取
element.style.width = '100px';       // 批量写入
// 或使用 requestAnimationFrame
requestAnimationFrame(() => {
  element.style.width = '100px';
});

// ✅ 使用 CSS 类批量修改
element.classList.add('new-width');
```

### 重绘（Repaint）

**触发条件：** 修改了不影响几何信息的样式

```javascript
// ✅ 只触发重绘，不触发重排
element.style.color = 'red';           // 改变颜色
element.style.backgroundColor = 'blue'; // 改变背景色
element.style.visibility = 'hidden';    // 改变可见性

// ✅ 重绘性能开销相对较小
```

**重排与重绘的关系：**
```
重排 (Reflow)                    重绘 (Repaint)
     ↓                               ↓
样式计算 → 布局 → 分层 → 绘制      仅绘制（跳过布局和分层）
     ↓                               ↓
性能开销大                        性能开销小
```

## 六、为什么 transform 效率高？

```javascript
// ❌ 使用 left/top 动画（触发重排）
element.style.left = '100px';  // 触发重排 → 重绘 → 合成
element.style.top = '100px';   // 触发重排 → 重绘 → 合成

// ✅ 使用 transform 动画（只触发合成）
element.style.transform = 'translate(100px, 100px)';  // 只触发合成
```

**性能对比：**
```
left/top 动画：
┌─────────┬─────────┬─────────┬─────────┐
│ 重排    │ → 重绘  │ → 合成  │ → 显示  │  主线程参与
└─────────┴─────────┴─────────┴─────────┘

transform 动画：
┌─────────┬─────────┐
│ 合成    │ → 显示  │           只在合成线程完成
└─────────┴─────────┘
```

**关键点：**
- `transform` 只影响**合成（Composite）**阶段，不影响布局、绘制等主线程步骤
- 动画（如 `animation`）使用 `transform` 时，甚至完全在**合成线程**完成，主线程无感知
- 因此，即使主线程被 JS 长时间阻塞，`transform` 动画依然流畅

```css
/* 推荐的动画属性 */
.animated-element {
  /* ✅ 高效：只触发合成 */
  transform: translateX(100px);
  opacity: 0.5;
  
  /* ❌ 低效：可能触发重排或重绘 */
  /* left: 100px; */
  /* width: 200px; */
}

/* 使用 will-change 提示浏览器优化 */
.optimized-animation {
  will-change: transform, opacity;
  transition: transform 0.3s ease, opacity 0.3s ease;
}
```

## 七、面试回答参考

### 开篇说明

"当浏览器的网络线程收到一篇文档后，会产生一个渲染任务，并将其传递给渲染主线程的消息队列。渲染主线程通过事件循环取出该任务，正式启动渲染流程。"

### 八步流程

"整个渲染过程可分为 8 个主要阶段：
1. **解析 HTML** → 生成 DOM 树 + CSSOM 树
2. **样式计算** → 得到带有最终样式的 DOM 树
3. **布局** → 生成布局树（包含几何信息）
4. **分层** → 将布局树分层（优化重绘）
5. **绘制** → 为每一层生成绘制指令
6. **分块** → 将每一层划分为多个小块
7. **光栅化** → 将每个小块转换成位图（GPU 加速）
8. **画** → 合成线程将位图合成并显示到屏幕"

### 重点问题

**CSS 与 JS 的阻塞：**
"CSS 不阻塞 HTML 解析，但 JS 会阻塞。因为 CSS 解析在预解析线程中完成，与主线程并行；而 JS 可能修改 DOM 树，所以主线程遇到 `<script>` 时必须暂停解析。"

**重排与重绘：**
"重排是修改了影响几何信息的操作（如宽高、边距、DOM 增删），会重新执行样式计算 → 布局 → 分层 → 绘制全流程；重绘是修改不影响几何信息的样式（如颜色、背景），仅重新生成绘制指令。重排性能开销大，应避免频繁触发。"

**transform 高效原因：**
"transform 只影响合成阶段，不涉及主线程的布局和绘制步骤，因此效率极高。即使主线程被 JS 长时间阻塞，transform 动画依然流畅。"

### 专业术语

尽量使用专业术语展现深度：Computed Style、Layout Tree、合成线程、GPU 进程、沙盒、光栅化、Draw Quads 等。
